**English Corner:**

`package.json 可以 discard 嗎?` 這句是中英混用的工程師日常說法，`discard` 用得很準確 —— 在 Git 語境中，「丟棄尚未提交的工作區變更」正是用 `discard`（SourceTree、VS Code 的按鈕就叫 Discard Changes）。

**自然的英文說法：**

- `Can I discard the changes to package.json?`（可以丟棄 package.json 的變更嗎？）
- `Is it safe to discard package.json?`（discard package.json 安全嗎？）

**近義詞辨析：**

| 動詞 | 語意 | 使用時機 |
|------|------|---------|
| `discard` | 丟棄未提交的變更 | 工作區的修改不要了 |
| `revert` | 用一個新 commit 抵銷舊 commit | 已提交、甚至已推送的內容 |
| `reset` | 把分支指標移回某個 commit | 改寫歷史，比較危險 |

這三個常被混用，但在 Git 中意思差很多。你這次要做的正是 `discard`，用字完全正確。

這次你的訊息是中文的問題回報單，格式很清楚。以下提供這類 bug report 的標準英文說法，這在跨國團隊或寫 GitHub issue 時很實用：

| 中文 | 標準英文欄位名 |
|------|--------------|
| 問題摘要 | Summary |
| 重現步驟 | Steps to Reproduce |
| 預期結果 | Expected Result |
| 實際結果 | Actual Result |

**描述這個問題的自然說法：**

- `Queries containing an ORDER BY clause fail on SQL Server, but run fine once the clause is removed.`（含 ORDER BY 的查詢在 SQL Server 上失敗，移除該子句後就正常）
- `We're concerned that dropping the sort would break the "latest 10,000 rows" requirement.`（我們擔心拿掉排序會破壞「最新 10,000 筆」的需求）

**用字重點：**

- **clause（子句）**：SQL 的組成單位就叫 clause —— `WHERE clause`、`ORDER BY clause`、`GROUP BY clause`。不要說 `ORDER BY sentence` 或 `ORDER BY command`。
- **run fine / work as expected**：描述「正常運作」的口語與正式說法，比 `is normal` 自然得多。
- **be concerned that...**：表達擔憂的正式說法，比 `worry about` 更適合書面回報。
